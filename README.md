# ColorMusic — цветомузыка для умной лампочки (Android 10+)

Приложение слушает звук (системный или микрофон), вычисляет громкость, низкие/средние/высокие
частоты, центроид и всплески, и меняет цвет и яркость лампочки Tuya / Smart Life.
Управление лампочкой идёт через Home Assistant.

## Архитектура

| Модуль (файл)                 | Назначение |
|-------------------------------|------------|
| `AudioCapture.kt`             | Захват звука: `AudioPlaybackCapture` (системный) или микрофон |
| `AudioAnalyzer.kt`            | RMS, FFT, полосы 20–250 / 250–2000 / 2000–12000 Гц, центроид, beat, AGC, сглаживание |
| `ColorMapper.kt`              | Признаки → HSV → RGB и яркость, палитры, safe-mode |
| `LightController.kt`          | Интерфейс лампы, реализация Home Assistant, ограничитель частоты, тест |
| `Settings.kt`                 | Настройки в EncryptedSharedPreferences (токен не в коде) |
| `ColorMusicService.kt`        | Foreground-сервис: конвейер захват → анализ → лампа, диагностика |
| `MainActivity.kt`             | UI на Jetpack Compose |

Конвейер: `AudioCapture.read` → `AudioAnalyzer.analyze` → `ColorMapper.map` → `LightCommandSender.offer`
(хранится только последнее состояние) → отправка не чаще 6 команд/с.

## Разрешения

- `RECORD_AUDIO` — захват звука (для системного режима Android также требует выдачи доступа к захвату при каждом запуске);
- `INTERNET` — запросы к Home Assistant в локальной сети;
- `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MEDIA_PROJECTION`, `FOREGROUND_SERVICE_MICROPHONE` — работа в фоне;
- `POST_NOTIFICATIONS` — уведомление о работающей службе (Android 13+).

## Зависимости

Android Studio (Ladybug или новее), JDK 17, Kotlin 2.0.20, Compose BOM 2024.09.00,
Material3, `security-crypto`, `okhttp`, `kotlinx-coroutines`. Больше ничего не нужно.

## Запуск

1. Откройте папку `ColorMusic` в Android Studio, дождитесь синхронизации Gradle
   (wrapper Android Studio создаст сама, если его нет).
2. Подключите телефон с включённой отладкой по USB, нажмите Run.
3. Заполните адрес Home Assistant, токен и `entity_id`, нажмите «Проверить лампочку».

Аудио не сохраняется на диск: буферы сразу передаются анализатору и отбрасываются.

## Подключение лампочки Tuya / Smart Life через Home Assistant

1. Добавьте лампочку в приложение Smart Life, убедитесь, что телефон и лампа в одной Wi-Fi сети.
2. Установите Home Assistant (Raspberry Pi, мини-ПК, Docker или HA OS) в той же сети.
3. В Home Assistant: Настройки → Устройства и службы → Добавить интеграцию → Tuya
   (или LocalTuya для полностью локального управления; для него нужен local key,
   который получают через Tuya IoT Platform). Для ускорения реакции лучше локальный вариант.
4. Найдите `entity_id` лампочки: Настройки → Устройства → лампочка → нужная сущность
   (вид `light.xxx`).
5. Создайте долгосрочный токен: в профиле Home Assistant → Безопасность → Долгосрочные токены.
6. Вставьте адрес (`http://IP:8123`), токен и `entity_id` в приложение.

Почему не Tuya Cloud напрямую: облачные запросы занимают от сотен миллисекунд до секунд
и ограничены по частоте, поэтому для цветомузыки не подходят. Локальный протокол Tuya
или Home Assistant дают заметно лучшую отзывчивость.

Лампа должна поддерживать цвет (RGB). Белая лампа будет менять только яркость.

## Выбор источника звука

- **Системный звук** — приложение слушает то, что играет на телефоне (например, Яндекс Музыка).
  Android спросит разрешение на захват, и его нужно выдавать при каждом запуске.
  Работает только для приложений, которые разрешают захват (`allowAudioPlaybackCapture`).
  Многие стриминговые приложения этого не разрешают.
- **Микрофон** — запасной режим. Работает всегда, но слышит звук из динамика вместе с шумами комнаты
  и с задержкой. Сделайте громкость музыки средней и держите телефон рядом с колонкой.

Если системный звук недоступен, приложение покажет сообщение и предложит микрофон.

## Известные ограничения

- Android 10+: системный захват зависит от приложения-источника. Защищённые потоки и некоторые
  приложения не отдают звук: будет тишина. Тогда остаётся микрофон.
- Android 14+: захват системного звука требует подтверждения при каждом запуске.
- Задержка: около 100–200 мс на анализ и захват, плюс сеть и лампа. Ощущается 300–500 мс.
  Для цветомузыки это приемлемо, но не идеально.
- Пользователь вводит `entity_id` вручную. Выбор из списка устройств из HA можно добавить через `/api/states`.
- Изменение адреса, токена и `entity_id` вступает в силу после «Стоп» и «Старт».
- Режим `safeMode` включён по умолчанию: плавные переходы, без вспышек на ударах (защита от эпилепсии).
- Код написан без сборки и тестирования на реальном устройстве. Возможны мелкие правки
  из-за версий библиотек. Ошибки сборки покажет Android Studio, их легко исправить.
